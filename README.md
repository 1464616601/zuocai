# 我的菜谱（Zuocai）

一个以「粘贴文本」为主的 Android 菜谱记录 App。把任意格式的菜谱文本丢进输入框，自动解析成结构化的菜名、食材和步骤；数据全部留在手机上。可选接入大模型，输入菜名直接生成菜谱。

## 功能

| 模块 | 说明 |
| --- | --- |
| 菜谱列表 | 两列卡片流，展示封面、菜名、难度 / 时长 / 份量 |
| 搜索 | 按菜名、描述、食材名模糊匹配，输入即搜（260ms 防抖） |
| 分类筛选 | 家常菜 / 汤羹 / 主食 / 凉菜 / 甜点 / 其他 |
| 排序 | 最近更新、按菜名、**使用最多**（打开次数 + 搜索命中次数，热度相同按最近更新兜底）。默认「使用最多」，手动换过会记住 |
| 详情页 | 大图封面、食材清单、编号步骤；有多套做法时顶部出现切换条，可在原做法和各变体间来回切换 |
| **文本录入** | 一个输入框，粘贴 Markdown / 纯文本，实时解析并显示「9 食材 · 4 步骤」，可展开预览核对 |
| **AI 生成** | 输入「洋葱炒肉」，调用大模型按其格式返回菜谱，一键填入输入框 |
| **AI 配图** | 按菜名与主料生成菜品图作为封面（`cogview-3-flash`，免费，带「AI生成」水印） |
| **AI 换做法** | 详情页右上角星形按钮，输入手头缺什么（如「没有大蒜」），AI 按现有做法给一版替代方案；生成后直接在详情页预览（界面与原做法一致），可保存为同一道菜的另一种做法，也可放弃 |
| **网络搜图** | 按菜名搜真实菜品照片，一屏 12 张候选，点一张自动裁成 4:3 设为封面，可换一批 |
| **导入 / 导出** | 首页右上角两个按钮，全库菜谱导出成单个 TXT，换手机时导入还原（文字完整，封面不跟随） |
| **放松小游戏** | 排序菜单里的「🎮 放松一下」，内置贪吃蛇 / 俄罗斯方块 / 推箱子 / 飞机大战 / 坦克大战 |
| 编辑 | 已有菜谱反向序列化成文本回填，整体重写即可 |
| 封面 | 相册选图 / 拍照，自动修正 EXIF 方向并压缩 |
| 删除 | 编辑页底部，二次确认，同时清理图片文件 |
| 防误退 | 有未保存修改时退出弹确认 |

### 文本解析支持的写法

解析器是纯本地规则实现，不依赖大模型，离线也可用。已验证的格式：

```markdown
# 花菜炒肉
### 食材
花菜半颗、瘦肉 200g、蒜 3 瓣、干辣椒可选、生抽 2 勺、盐、少许白糖、食用油
### 步骤
1. 花菜掰小朵，盐水浸泡 5 分钟，开水下锅焯**30 秒**捞出沥干。
2. 热锅放油，肉片下锅大火炒至变色盛出。
> 小贴士：焯水别太久，不然花菜软塌不清脆。
```

- 标题层级不限（`#` / `##` / `###`），也支持 `**食材**：`、`食材：`、纯文本「食材」独占一行
- 菜名可来自 `# 标题`、`菜名：xxx`、或首个非空行
- 食材支持 `、，,；` 分隔，自动拆分「名称 + 用量」，不含空格的「花菜半颗」也能正确拆开
- 步骤支持 `1.` `1、` `(1)` `①` `-` 等编号；未编号的行会并进上一步
- `>` 引用块或「小贴士：」开头的内容归入描述
- 自动清理 `**粗体**`、`*斜体*`、`` `代码` ``、链接等 Markdown 标记
- 分类按菜名与食材关键词自动推断（含「汤」→ 汤羹，含「饭/面/粥」→ 主食，含「凉拌」→ 凉菜…）

## 技术栈

- 语言：Kotlin 1.9.24
- 构建：AGP 8.7.3 / Gradle 8.11.1 / JDK 17
- 最低系统：Android 7.0（API 24），目标 API 34
- 界面：AndroidX AppCompat + Material Components（View 体系，非 Compose）
- 存储：SQLite（SQLiteOpenHelper 原生 API），食材与步骤以 JSON 存在同一行
- 图片：自实现采样解码 + LruCache，无第三方图片库
- 网络：`HttpURLConnection` 直连 OpenAI 兼容接口，不引入 OkHttp/Retrofit
- 依赖总量：7 个 AndroidX/Material 组件 + 1 个测试框架（junit，仅测试期）

## 接入大模型（可选）

App 内置了一个默认 Key（`ApiConfig.DEFAULT_API_KEY`），装上就能用 AI 生成菜谱、AI 换做法和 AI 配图，不需要任何配置。想换成自己的 Key，在设置页填写即可，会覆盖默认值。

> 注意：Key 编译进安装包就等于公开。个人自用没问题，如果公开发布，请换成服务端代理转发，或接受内置 Key 额度被消耗的风险。

### 免费 API 怎么选

| 平台 | 免费政策 | 网页版可用 | 备注 |
| --- | --- | --- | --- |
| **智谱 GLM-4-Flash** | 官方免费文本模型，实测 Key 可直接调通、不计费 | ❌ 不返回 CORS 头 | APK 首选，中文最自然 |
| **硅基流动** | 注册送 2000 万 Token，9B 以下模型永久免费 | ✅ 返回 `Access-Control-Allow-Origin: *` | 网页版唯一可用 |
| 百度千帆 ERNIE-Speed | 永久免费，QPS 50 | 未验证 | 备选 |
| 讯飞星火 Spark-Lite | 永久免费 | 未验证 | 备选 |

**结论**：APK 内优先智谱 `glm-4-flash`；网页版只能用硅基流动（跨域限制）。

### 放松小游戏

入口藏在左下角的排序菜单里（第二组、分隔线下方），不占主界面位置。
五个游戏都是纯 Canvas 实现，不依赖任何游戏引擎，最高分存本机。

| 游戏 | 玩法 | A / B 键 |
| --- | --- | --- |
| 贪吃蛇 | 15×22 格，吃到红点 +10 分，越吃越快 | 不需要 |
| 俄罗斯方块 | 10×18 格，带落点投影，消行按 1/2/3/4 行给 100/300/500/800 | A 旋转 · B 直接落底 |
| 推箱子 | 三关，箱子推到圆点上，全清进下一关 | A 撤销 · B 重来本关 |
| 飞机大战 | 自动开火，三条命，击毁敌机 +10 | 不需要 |
| 坦克大战 | 守住底部基地，击毁敌方坦克 +20，砖墙可被打掉 | A 开炮 |

**两端各自实现，逻辑对齐**：网页版在 `web/games.js`（一个文件装下五个游戏），
APK 在 `app/src/main/java/.../game/` 下每游戏一个类，共用 `Game` 接口。

几个踩过的坑，写在这里免得以后重犯：

- **贪吃蛇不能一进游戏就动**。第一版按 150ms/步自动前进，玩家还没反应过来就撞墙了。
  改成「按第一个方向键才开始」，`label` 显示「按方向键开始」。
- **坦克的敌人会卡在顶部下不来**。出生点 y=20，而移动判定要求 `ny > T`（坦克尺寸 32），
  永远不满足，只能原地随机转向。把下界改成 6 才对。
- **坦克的玩家出生点压在基地上**。基地在屏幕正中，玩家原来也在正中，视觉上糊成一团。
  挪到基地左侧一格半。
- **`♥` 字符在缺字体的环境会画成豆腐块**。生命值原本用 `♥♥♥` 表示，
  无头浏览器里直接变成灰色方块，改成「生命 3 / 3」。
- **只在游戏结束才存最高分**，中途退出就白玩了。改成退出时也存（网页版在返回按钮里，
  APK 在 `onPause`/`onDestroy` 里）。
- **撞墙那一帧蛇头会越界**，绘制时画出画布外，加个坐标判断跳过。

### 导入导出的格式

数据只存本机，换手机靠 TXT 搬运。首页右上角：

- **导入**（下箭头）：选一个 TXT，批量入库
- **导出**（上箭头）：选保存位置，全库写成一个文件

导出内容长这样，每道菜一段：

```
==========  菜谱 1  ==========

# 红烧肉

@分类：家常菜
@时长：60分钟
@份量：4人份
@难度：中等

### 食材
五花肉 500g、冰糖 30g、生抽 2 勺

### 步骤
1. 五花肉切块，冷水下锅焯水去腥。
2. 冰糖小火炒出糖色，下肉块翻炒上色。

> 小贴士：冰糖先炒糖色，肉才红亮不发黑。
```

设计上的几个取舍：

- **用 `@键：值` 存元信息**：纯 Markdown 表达不了分类和份量。选这种写法是因为它一眼能看懂、
  手写也不别扭，而且解析器遇到不认识的行不会误判成食材
- **用 `====` 分段**：菜谱正文里几乎不会出现连续 4 个等号，比用 `---` 安全
  （Markdown 分隔线常用 `---`，会和正文冲突）
- **导出带 UTF-8 BOM**：否则 Windows 记事本把中文显示成乱码，用户会以为文件坏了。
  导入端会剥掉 BOM，不影响解析
- **导入支持 GBK**：记事本「另存为 ANSI」存的是 GBK，按 UTF-8 硬解全是乱码，
  所以先严格试 UTF-8，失败再回落 GBK
- **同名跳过**：按菜名精确匹配。重复导入同一文件不会产生一堆重复项，
  但同名的新菜谱也进不来——想覆盖就先删掉旧的
- **封面不导出**：TXT 存不了二进制。跨手机迁移后需要重新配图（可再用网络搜图）

### 网络搜图

封面来源优先级建议：**自己拍 > 网络搜图 > AI 生成**。搜来的是真实菜品照片，
配色、汤汁光泽、配料比例都对得上，比 `cogview-3-flash` 生成的图真实得多。

实现方式：Bing 图片搜索 → 解析结果页的 `m` 属性 JSON（含原图 `murl`、缩略图 `turl`、
来源页 `purl`）→ 过滤掉付费图库 → 并行拉缩略图 → 用户点选后下载原图并**居中裁成 4:3**。

几个实现细节：

- **必须带 `Accept-Language: zh-CN`**：否则 Bing 按 IP 猜语言，中文菜名可能返回英文结果集
- **下载原图要带 Referer**（原站点页），很多站有防盗链；失败时退回 `cn.bing.com` 再试一次
- **过滤付费图库**：699pic、588ku、nipic、freep 等站的图铺满水印，直接在服务端剔除
- **4:3 裁切**：与列表卡片、详情页封面的比例一致，裁完再压到长边 1600 / JPEG 88

实测覆盖（抓取前 3 张人工核对）：宫保鸡丁、青椒土豆丝、番茄炒蛋、红烧肉、
洋葱炒肉、可乐鸡翅、蒜蓉油麦菜 **全部命中，无一错配**。

> **版权提示**：搜来的图版权归原站点和作者所有。个人做菜谱记录、自己看没问题，
> 但不要用于公开分享、商用或二次分发。要完全干净就用自己拍的照片。

### 图像生成

`cogview-3-flash` 免费，返回带签名的临时 URL（约 7 天过期），所以两端都是**立刻下载转存本地**，
不依赖远端链接。生成的图右下角有「AI生成」水印，属平台合规标识，未做去除处理。
卡片封面按 4:3 裁切时水印通常落在裁切区外，但文件本身保留标识。

### 智谱模型实测对比（2026-10，标准 API Key）

用同一个 Key 逐个试出来的结果，比文档更可靠：

| 模型名 | 结果 | 结论 |
| --- | --- | --- |
| `glm-4-flash` | ✅ 正常返回，13 tokens | **推荐**，快且免费 |
| `glm-4-flash-250414` | ✅ 正常返回 | 与上面等价，可作备选 |
| `glm-4.7-flash` | ⚠️ HTTP 429「访问量过大」 | 模型更新但免费额度限流严重 |
| `glm-4.5-flash` | ⚠️ 成功但 `content` 为空 | 默认开深度思考，思考 token 吃满额度 |

实测「洋葱炒肉」生成耗时约 3 秒，返回 9 项食材 / 6 个步骤，被解析器 100% 正确识别。

### 配置

App 内「新建菜谱 → 齿轮图标」进入设置，可直接点「智谱 GLM-4-Flash」一键填充，再填 Key 即可。
填完可点「测试连接」验证，不用盲试。

| 项 | 智谱 | 硅基流动 |
| --- | --- | --- |
| API 地址 | `https://open.bigmodel.cn/api/paas/v4` | `https://api.siliconflow.cn/v1` |
| 模型名 | `glm-4-flash` | `Qwen/Qwen2.5-7B-Instruct` |
| API Key | 控制台「标准 API Key」页新建 | 控制台获取 |

Key 存在本机 SharedPreferences（网页版为 localStorage），不上传。接口走 OpenAI 兼容格式，换成任何兼容服务只需改这三项。

## 构建

前置：JDK 17、Android SDK（platform 34 + build-tools 34.0.0）。

```bash
# 本机已装 Gradle 8.11.1 的情况：
gradle assembleRelease
# 或用仓库自带 wrapper（distributionUrl 已指向腾讯云镜像，国内可直接拉）：
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk

# 解析器回归测试
gradle testReleaseUnitTest
```

`local.properties` 中的 `sdk.dir` 需指向本机 Android SDK 路径；`gradle.properties`
中的 `org.gradle.java.home` 指向 JDK 17（AGP 8.x 不支持 JDK 8）。
依赖仓库已在 `settings.gradle.kts` 中配置阿里云镜像，避免 google() 直连超时。

## 安装到手机

1. 把 `zuocai-v1.1.apk` 传到手机（数据线 / 微信文件传输 / 网盘均可）。
2. 覆盖安装旧版本可直接升级（签名一致，versionCode 2 > 1）。
3. 首次进入自带 41 道内置菜谱（来自 `app/src/main/assets/default_recipes.txt`，
   网页版对应 `web/default-recipes.js`，两份内容一致）。导入按菜名去重，
   所以升级安装时只会补上库里缺的菜，不会和已有菜谱重复。
   每条菜谱的封面由 `@封面：cNN` 指定，图片在 `assets/covers/`（网页版 `web/covers/`），
   首次启动会复制到 `filesDir/images/`，之后和用户自己选的封面走同一套渲染逻辑。

> 本 APK 使用自签名证书（`keystore/zuocai-release.jks`，别名 `zuocai`，口令 `zuocai2024`）。
> 后续升级必须用同一份 keystore 签名，否则无法覆盖安装，请勿丢失该文件。

## 在电脑上预览（无需装 APK）

`web/` 目录是功能等价的网页版，用来在不装 APK 的情况下点着测交互。

| 文件 | 用法 |
| --- | --- |
| `web/启动预览.bat` | **推荐**，双击启动本地服务并打开浏览器，AI 可直接用 |
| `web/preview.html` | 单文件、零依赖，双击即开；但没有本地代理，AI 需自己填 Key |
| `web/index.html` + `app.js` / `parser.js` / `app.css` | 开发用的分文件版本 |
| `web/serve.py` | 本地服务：静态文件 + `/api/chat` 代理转发 |
| `web/config.local.json` | 本机 API Key（已被 .gitignore 排除，不会提交） |

### 为什么需要本地代理

智谱只在 POST 响应里返回 `Access-Control-Allow-Origin`，OPTIONS 预检不返回，
浏览器会在预检阶段就拦下请求，前端直连必然失败。

`serve.py` 把请求放在服务端转发，浏览器只访问 `127.0.0.1`，因此：

- 不受跨域限制，智谱可用
- API Key 留在服务端文件里，不进浏览器、不进 HTML
- 换模型或 Key 只需改 `config.local.json` 后重启服务

重新生成单文件版本（改完 `app.js` / `parser.js` / `app.css` 后执行）：

```bash
cd web
python rebuild.py
```

**网页版与 APK 的差异**：

- 一致：页面结构、配色、间距、字号层级、交互流程、校验规则、解析算法（`parser.js` 与 `RecipeParser.kt` 逐条对齐，双端同过 10 个用例）、空状态、防误退、搜索防抖、排序逻辑
- 不一致：字体由浏览器渲染（Android 用系统思源黑体）；没有系统相机与相册选择器；网页版 AI 必须走本地服务，APK 内置直连

适合用它验证：文案是否通顺、信息层级是否清楚、粘贴解析是否正确、AI 生成效果、表单流程是否顺手、按钮是否够大、边界情况是否崩。  
不适合用它验证：安装包兼容性、真机滑动流畅度、拍照效果、深色模式。

## 可自定义的地方

| 想改什么 | 改哪里 |
| --- | --- |
| 应用名 | `res/values/strings.xml` 的 `app_name` |
| 主色调 | `res/values/colors.xml` 的 `brand` 系列 |
| 分类项 | `data/RecipeCategory.kt` 枚举 + `strings.xml` 文案 |
| 启动图标 | 替换 `res/mipmap-*/ic_launcher.png`，或改 `res/drawable/ic_launcher_fg.xml` |
| 包名 | `app/build.gradle.kts` 的 `namespace` 与 `applicationId`（需同步改目录名） |
